Диагностическая страница 1C HTML Shell

Назначение: открыть эту страницу в обычном браузере или внутри 1С через Поле HTML-документа и получить профиль среды запуска.

Профиль показывает, какие возможности HTML, CSS, JavaScript, ввода и прокрутки доступны в этой среде. Он помогает решить, можно ли дальше проектировать покупательскую HTML-оболочку для кассы самообслуживания.

Это не касса и не проверка готовности кассы.

Страница не проверяет РМК, чек, оплату, ККТ, фискализацию, печать и маркировку. Для этого нужны отдельные проверки 1С/RMK Adapter.

JavaScript ещё не запустился.

Если это сообщение не исчезает, среда запуска не выполнила базовый JavaScript. Сделайте скриншот и передайте его команде проекта. JSON-отчёт в этом случае может быть недоступен.

Открыть витрину

Что проверяет инструмент

  • Отрисовку HTML и базовых CSS-возможностей.
  • Работу простого JavaScript и JSON.
  • Касания, нажатия, фокус поля ввода и прокрутку.
  • Возможность сформировать, скопировать и скачать JSON-отчёт.
  • Пробную загрузку CSS/JavaScript из встроенного data:-ресурса. Это не доказывает загрузку отдельных файлов по URL.
  • Статус обмена HTML ↔ 1С. Без 1С Diagnostic Loader он будет "Не подключено"; Slice 2 проверяет этот обмен отдельно.

Что не проверяется

  • Добавление товара в чек, удаление товара, текущий чек и РМК.
  • Оплата, эквайринг, ККТ, фискализация, печать, маркировка.
  • Кассовые права и внутренние процедуры конфигурации 1С.

      Инструкция для 1С-специалиста

      Slice 2 - это следующий отдельный шаг после базовой диагностики: небольшой периметрный диагностический адаптер между HTML-страницей и кодом 1С. Он проверяет только двусторонний обмен HTML → 1С → HTML, а не РМК и не кассовые операции. Подробное задание: 1C_HTML_SHELL_DIAGNOSTIC_GUIDE_FOR_1C_SPECIALIST.md. Исходники для самостоятельной сборки внешней обработки: tools/1c-diagnostic-loader/. Откройте эти материалы в обычном браузере, если Поле HTML-документа 1С не должно уходить со страницы диагностики.

      1. Slice 1: откройте URL этой страницы в форме 1С через Поле HTML-документа и получите базовый JSON-профиль среды.
      2. Для повторной проверки передайте новый runId, например: /diagnostics/1c-html-shell?runId=test-001&terminalLabel=test-terminal&v=manual-test.
      3. runId - метка конкретного запуска диагностики. terminalLabel - безопасная подпись терминала, например номер тестового рабочего места.
      4. Если в базовом отчёте указано "Обмен HTML ↔ 1С: Не подключено", это не ошибка. Это значит, что Slice 2 ещё не запускался.
      5. Slice 2: соберите или адаптируйте исходники внешней обработки и подключите их в тестовой базе.
      6. Проверьте round-trip: HTML отправляет безопасную команду diag.ping, 1С принимает её и возвращает ответ в HTML с тем же requestId.
      7. После Slice 2 передайте команде итоговый JSON, журнал обработки и комментарий, какой транспорт сработал: href/navigation, DOM mailbox, direct JS call или fallback.
      8. Готовый файл .epf пока не собран. 1С-специалист собирает внешнюю обработку в своей тестовой базе и проверяет обмен на целевой версии платформы.
      9. Не добавляйте в отчёт товары, чеки, суммы покупок, персональные данные, токены, пароли, данные карт, фискальные данные и внутренние ссылки на объекты 1С.
      10. Этот тест не проверяет РМК, оплату, ККТ, фискализацию, печать и маркировку.
