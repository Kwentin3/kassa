# Guide: 1C HTML Shell Diagnostic For 1C Specialist

Дата: 2026-05-19
Статус: Slice 1 guide
Назначение: короткая инструкция для 1С-специалиста

## Что открыть

Откройте диагностическую страницу:

```text
https://kassa.speechbattle.com/diagnostics/1c-html-shell
```

Для повторной проверки используйте новый `runId`:

```text
https://kassa.speechbattle.com/diagnostics/1c-html-shell?runId=test-001&terminalLabel=test-terminal&v=manual-test
```

## Где открыть в 1С

Откройте URL внутри формы 1С через `Поле HTML-документа`.

Если страница открывается только в обычном браузере, это полезная предварительная проверка, но она не доказывает, что страница работает внутри 1С.

## Параметры URL

| Параметр | Что значит |
|---|---|
| `runId` | Метка конкретного запуска диагностики. Меняйте при повторной проверке. |
| `terminalLabel` | Безопасная подпись терминала, например `test-terminal-01`. Не пишите секреты. |
| `v` или `build` | Метка версии диагностической страницы, помогает обойти кэш и сравнить отчеты. |
| `verdictScope` | Можно явно указать `one_c_html_field_unconnected`, если страница открыта внутри 1С без loader. |

## Что сделать после запуска

1. Дождитесь завершения фаз диагностики 0-6.
2. Нажмите тестовую кнопку в разделе "Ввод, касания и прокрутка".
3. Прокрутите тестовый блок.
4. Введите текст в тестовое поле.
5. Заполните блок "Ручные наблюдения".
6. Нажмите "Скопировать JSON" или "Скачать JSON".
7. Если автоматическое копирование не работает, выделите JSON вручную и скопируйте его.
8. Передайте JSON команде проекта.

## Что значат проверки resource.loading.css/js

В Slice 1 диагностическая страница остается одним HTML-файлом. Поэтому проверки `resource.loading.css` и `resource.loading.js` не загружают реальные отдельные файлы с сайта.

Они подключают встроенные `data:`-ресурсы и показывают только то, что среда запуска умеет динамически добавить CSS/JavaScript ресурс после открытия страницы.

Даже если эти проверки успешны, это не доказывает, что Поле HTML-документа 1С загрузит отдельные CSS/JS-файлы по URL. Загрузку реальных отдельных файлов нужно проверять отдельно перед split-assets вариантом.

## Что значит "обмен HTML ↔ 1С не подключён"

В Slice 1 страница не содержит 1С Diagnostic Loader. Поэтому статус обмена HTML ↔ 1С ожидаемо равен:

```json
{
  "bridge": {
    "status": "not_connected"
  }
}
```

Это не ошибка страницы. Для проверки обмена HTML ↔ 1С нужен следующий этап: минимальный 1С Diagnostic Loader с командами `diag.ping`, `diag.hrefTransport`, `diag.domMailbox` и direct JS call test.

## Что тест не проверяет

Диагностическая страница не проверяет:

- РМК;
- текущий чек;
- добавление или удаление товара;
- оплату;
- эквайринг;
- ККТ;
- фискализацию;
- печать;
- маркировку;
- кассовые права;
- внутренние процедуры конфигурации 1С.

Статус РМК-адаптера в Slice 1 должен быть:

```json
{
  "rmkAdapter": {
    "status": "not_tested"
  }
}
```

## Что нельзя отправлять в отчёте

Не добавляйте в поля наблюдений и не передавайте в отчете:

- товары;
- чеки;
- суммы реальных покупок;
- персональные данные;
- фискальные данные;
- токены;
- пароли;
- данные карт;
- секреты;
- внутренние ссылки на объекты 1С;
- содержимое cookies;
- содержимое localStorage;
- содержимое буфера обмена.

Отчет должен содержать только технический профиль среды запуска и ручные наблюдения.
