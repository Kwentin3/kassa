# Visual Contracts - Self-Checkout Terminal MVP

Дата: 2026-05-19  
Назначение: зафиксировать правила адаптивной визуализации терминала, чтобы экраны не ломались на планшете, kiosk viewport или большом touch display.

## Базовый контракт viewport

- Приложение не задаёт `min-width` на `body`.
- Корневой экран использует `100dvh` и `width: 100%`, а не жесткий `w-screen`.
- Каждый экран сам определяет scroll-зону через `.screen-body` и `.scroll-y`.
- Горизонтальный скролл не является штатным поведением customer flow.
- Если контента больше, чем помещается в viewport, скролл должен быть вертикальным внутри рабочей зоны экрана.

## Layout Contract

Основные layout-классы находятся в `src/styles/index.css`:

- `.app-screen`: базовый контейнер экрана.
- `.app-header`: адаптивная шапка.
- `.screen-body`: область под header.
- `.scroll-y`: явная вертикальная scroll-зона.
- `.cart-layout`: корзина + рабочая область.
- `.catalog-layout`: категории + сетка товаров.
- `.search-layout`: экранная клавиатура + результаты.
- `.product-grid`: адаптивная сетка карточек через `auto-fit`.
- `.product-card`: стабильная карточка товара.
- `.responsive-panel`: центрированные панели оплаты, ошибок, staff и receipt.
- `.visual-contract-grid`: панели demo/branding без фиксированных колонок.

Правило: новые экраны должны использовать эти классы или добавлять такой же явный контракт, а не новый набор случайных `w-[...]`, `grid-cols-[...]`, `h-[calc(...)]` без причины.

## Product Card Contract

- Карточка товара не должна иметь фиксированную ширину.
- Карточка товара не должна растягиваться на всю ширину контейнера, если в результате поиска осталась 1-2 позиции.
- Сетка товаров использует flex-wrap и фиксированный card-width token, чтобы одиночные карточки оставались карточками, а не широкими баннерами.
- Изображение товара находится в стабильном thumbnail-контейнере с ограниченной высотой `--product-image-height`.
- Если внешний image asset недоступен, карточка показывает fallback initials.
- Текст карточки должен оставаться внутри карточки; длинные названия не должны расширять колонку.
- Название товара ограничено двумя строками; бренд/фасовка обрезаются ellipsis.
- CTA внутри карточки остаётся touch-first, но не должен делать карточку выше необходимого.
- Карточка товара должна иметь мягкую тень, чтобы отделяться от фона и соседних карточек.
- Нажатие на CTA внутри карточки даёт feedback на самой карточке: лёгкое проседание, усиление border и краткий overlay.
- Hover/lift используется только для pointer devices; на touch-экранах основной эффект — pressed-state.
- При `prefers-reduced-motion: reduce` карточка не должна анимировать scale/translate.

Element-level tokens:

- `--product-card-width`: рабочая ширина карточки.
- `--product-card-max`: максимальная ширина карточки на tablet/desktop.
- `--product-image-height`: максимальная высота изображения внутри карточки.

Rule of thumb: при 1-2 карточках на экране карточка остаётся компактной; пустое пространство остаётся вокруг сетки, а не превращается в растянутую карточку.

## Breakpoints

Основной demo target: Android tablet 10-13" landscape.

Secondary adaptation:

- `max-width: 900px` или portrait: двухколоночные layouts переходят в одну колонку.
- Категории каталога на узких экранах становятся wrap-grid.
- Cart panel переносится под рабочую область и получает вертикальный скролл.
- Decorative idle visual может уменьшаться или скрываться, но primary CTA должен оставаться доступным.

## Interaction Contract

- Touch targets не меньше 56-64px для основных действий.
- Focus state видимый через `:focus-visible`.
- Disabled state явный через opacity/cursor.
- Основной CTA не должен исчезать из видимой области без доступного вертикального скролла.
- Help и DEMO controls должны оставаться различимыми и не смешиваться с товарными карточками.

## Что запрещено

- Глобальный `body min-width` для имитации планшета.
- Необоснованные fixed widths для основных экранов.
- Горизонтальный overflow как способ “вместить” каталог.
- Карточки товаров с шириной, зависящей от длины текста.
- Изображения, которые растягивают карточку или меняют размер layout после загрузки.

## Verification Notes

Минимальная проверка перед деплоем:

- `npm run typecheck`
- `npm run test:run`
- `npm run build`
- `npm run visual:cards` for Playwright smoke against the deployed/demo URL;
- открыть catalog/search/cart/payment/receipt на `https://kassa.speechbattle.com`;
- проверить, что карточки товаров оборачиваются в сетке и не уходят за viewport;
- проверить, что карточки имеют depth shadow и нажатие на CTA визуально отзывается без изменения layout;
- проверить, что скролл вертикальный и находится внутри screen body;
- проверить, что product images либо загрузились, либо показали fallback initials.
