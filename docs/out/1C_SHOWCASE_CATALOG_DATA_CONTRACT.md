# 1C Showcase Catalog Data Contract

Дата: 2026-05-21
Статус: draft v0.1 для первого перехода от mock-каталога к каталогу 1С

## Назначение

Контракт описывает безопасный JSON, который 1С передает HTML-витрине для отображения групп и карточек товаров.

Это не контракт РМК, чека, оплаты, ККТ, фискализации или маркировки. HTML-витрина только принимает каталог, валидирует базовую структуру и показывает группы/товары. Корзина и все кассовые сценарии на этом этапе остаются demo-only.

## Архитектурное правило

1С готовит безопасный витринный JSON.

HTML-витрина:

- принимает JSON;
- валидирует базовую структуру;
- показывает группы;
- показывает карточки товаров;
- использует placeholder, если нет изображения;
- скрывает `visible=false`;
- скрывает `available=false` в первом production-like срезе;
- не делает кассовых операций;
- не знает внутренние ссылки объектов 1С.

`id` группы и товара должны быть opaque string. HTML не должен получать или разбирать внутренние ссылки 1С.

## Non-negotiable Rule

Каталог в runtime передается только нативно из 1С в HTML.
Пользователь не загружает и не вставляет JSON вручную.

## Delivery Constraints

Этот JSON не предназначен для ручной вставки пользователем в HTML.

Разрешенные runtime paths:

- primary: 1С вызывает `window.Showcase.receiveCatalog(catalogJsonString)` через direct JS call;
- native fallback: 1С записывает JSON в согласованный DOM mailbox, HTML считывает его и вызывает `receiveCatalog()`;
- last resort: 1С формирует HTML/макет/строку с embedded catalog и загружает это в `Поле HTML-документа`.

Developer sample JSON допускается только как fixture для разработки, автотестов и smoke-тестов. Он не является пользовательским сценарием, runtime-способом доставки или требованием к 1С-программисту загружать JSON в витрину руками.

HTML не должен запрашивать этот JSON у пользователя.

## Root Object

Минимальная структура:

```json
{
  "contractVersion": "0.1",
  "source": "1c",
  "generatedAt": "2026-05-20T12:00:00",
  "catalogId": "showcase-default",
  "currency": "RUB",
  "groups": [],
  "products": []
}
```

Поля:

| Поле | Обязательное | Тип | Правило |
|---|---:|---|---|
| `contractVersion` | да | string | Для первого среза `"0.1"` |
| `source` | да | string | Для 1С `"1c"` |
| `generatedAt` | да | string | ISO 8601 datetime |
| `catalogId` | да | string | Opaque id витринного каталога |
| `currency` | да | string | Валюта по умолчанию, сейчас `"RUB"` |
| `groups` | да | array | Массив групп |
| `products` | да | array | Массив товаров |

## Group

Пример:

```json
{
  "id": "group-drinks",
  "parentId": null,
  "title": "Напитки",
  "sortOrder": 10,
  "visible": true,
  "image": null,
  "icon": null
}
```

Обязательные поля группы:

| Поле | Тип | Правило |
|---|---|---|
| `id` | string | Opaque id группы. Не внутренняя ссылка 1С |
| `title` | string | Показываемое название группы |
| `sortOrder` | number | Чем меньше, тем раньше группа |
| `visible` | boolean | `false` означает не показывать группу |

Optional поля группы:

| Поле | Тип | Правило |
|---|---|---|
| `parentId` | string или null | Для будущей вложенности. В первом UI можно игнорировать |
| `image` | string или null | URL/base64/data-id только после отдельного решения по картинкам |
| `icon` | string или null | Безопасный ключ иконки или null |

Правила:

- `id` уникален внутри `groups`.
- `title` не пустой после trim.
- `sortOrder` число, не строка.
- `visible=false` скрывает группу.
- Если вложенность не нужна, `parentId` передается как `null` или не используется.

## Product

Пример:

```json
{
  "id": "product-001",
  "groupId": "group-drinks",
  "title": "Вода питьевая 0,5 л",
  "shortTitle": "Вода 0,5 л",
  "price": 45,
  "currency": "RUB",
  "image": null,
  "badges": [],
  "available": true,
  "visible": true,
  "requiresStaff": false,
  "ageRestrictedMock": false,
  "sortOrder": 10
}
```

Обязательные поля товара:

| Поле | Тип | Правило |
|---|---|---|
| `id` | string | Opaque id товара. Не внутренняя ссылка 1С |
| `groupId` | string | Должен ссылаться на существующую visible-группу |
| `title` | string | Показываемое название |
| `price` | number | Цена в основных единицах валюты, например `45` или `45.5` |
| `currency` | string | Сейчас `"RUB"` |
| `available` | boolean | `false` не добавляется в demo-корзину |
| `visible` | boolean | `false` не показывается |
| `sortOrder` | number | Чем меньше, тем раньше товар внутри группы |

Optional поля товара:

| Поле | Тип | Правило |
|---|---|---|
| `shortTitle` | string | Короткое название для fallback/поиска |
| `image` | string или null | URL или null; если null/битая, HTML показывает placeholder |
| `badges` | string[] | Короткие публичные бейджи: `Акция`, `Новинка`, `Хит` |
| `requiresStaff` | boolean | Demo-флаг: показать сценарий сотрудника |
| `ageRestrictedMock` | boolean | Demo-флаг: возрастное ограничение без реальной проверки |
| `description` | string | Краткое публичное описание, если понадобится карточке vNext |
| `barcode` | string | Штрихкод, если нужен для поиска/сканера vNext |
| `unit` | string | Например `шт`, `кг`, `л` |
| `quantityStep` | number | Например `1`, `0.1`; в первом UI можно игнорировать |

Правила:

- `id` уникален внутри `products`.
- `title` не пустой после trim.
- `price` должен быть числом, а не строкой `"45 руб."`.
- `currency` товара должен совпадать с root `currency`, пока multi-currency не проектируется.
- `badges` должны быть короткими публичными строками, без внутренних кодов.
- `image=null` является нормальным состоянием.
- `requiresStaff` и `ageRestrictedMock` остаются mock-state, не реальная авторизация.

## Что нельзя передавать

Нельзя передавать в этот JSON:

- внутренние ссылки объектов 1С;
- GUID/UUID, если по ним можно восстановить внутреннюю структуру базы;
- себестоимость;
- закупочные цены;
- остатки, если это не согласовано отдельным контрактом;
- персональные данные;
- данные чеков;
- данные оплат;
- фискальные данные;
- секреты;
- токены;
- строки подключения;
- технические имена регистров, документов, планов видов характеристик;
- служебные комментарии сотрудников;
- признаки, которые раскрывают внутреннюю бизнес-логику клиента.

Если 1С нужен стабильный id, она должна подготовить отдельный безопасный витринный идентификатор.

## Правила видимости и доступности

Первый срез выбирает консервативное поведение:

| Состояние | Поведение HTML |
|---|---|
| `group.visible=false` | Группа не показывается |
| `product.visible=false` | Товар не показывается |
| `product.available=false` | Товар не показывается в production-like каталоге первого среза |
| `image=null` | Показать placeholder |
| `image` битая/недоступная | Показать placeholder |
| `requiresStaff=true` | Показать карточку, при добавлении открыть mock-сценарий сотрудника |
| `ageRestrictedMock=true` | Показать карточку, при добавлении открыть mock-сценарий сотрудника |

Причина выбора по `available=false`: в первом реальном каталоге безопаснее не показывать товар, который нельзя добавить даже в demo-корзину. Отдельный режим **"показывать недоступные как disabled"** можно добавить позже, если это потребуется бизнесу.

## Валидация

HTML должен выполнить базовую валидацию перед заменой текущего каталога.

Root:

- `contractVersion` поддерживается;
- `source === "1c"`;
- `groups` и `products` являются массивами;
- `currency` задана и поддерживается;
- размер payload не ломает V8WebKit и controlled scroll-зоны.

Groups:

- если `id` пустой, группа invalid;
- если `title` пустой, группа invalid;
- если `sortOrder` отсутствует или не число, можно поставить `0` только в test fixture; для 1С-выгрузки это ошибка;
- если `visible=false`, группу не показывать;
- если ids дублируются, оставить первый валидный или отклонить каталог целиком. Для первого среза предпочтительно отклонить каталог и показать ошибку диагностики.

Products:

- если `groupId` товара не найден среди visible-групп, товар не показывать;
- если `price` отсутствует, товар не показывать;
- если `price` не число, товар не показывать;
- если `title` пустой, товар не показывать;
- если `visible=false`, товар не показывать;
- если `available=false`, товар не показывать в первом срезе;
- если `image` битая/null, использовать placeholder;
- если `badges` не массив, считать `[]`;
- если `sortOrder` отсутствует или не число, можно поставить `0` только в test fixture; для 1С-выгрузки это ошибка;
- если данных слишком много, `productGrid` должен использовать внутренний scroll и не ломать layout.

Не показывать покупателю технический JSON, stack trace или внутренние ошибки валидации.

## Сортировка

Группы:

```text
visible groups -> sort by sortOrder asc -> title asc as tie-breaker
```

Товары:

```text
visible + available products -> groupId match -> sort by sortOrder asc -> title asc as tie-breaker
```

`sortOrder` задает порядок, а не позицию в массиве. 1С может выгружать массивы в любом порядке, HTML нормализует.

## Поддержка текущего visual contract

Контракт должен поддерживать текущие edge cases:

- длинные названия;
- товар без картинки;
- бейджи;
- товар **"нужен сотрудник"**;
- товар **"возрастное ограничение"** как mock-state;
- сортировка групп;
- сортировка товаров;
- доступность товара;
- видимость товара.

Для картинок первый безопасный вариант: `image=null` и HTML placeholder. Реальные картинки подключать только после отдельного решения по источнику, размеру, кешированию и доступности внутри 1С HTML-поля.

## Versioning

`contractVersion: "0.1"` означает первый безопасный витринный каталог.

Совместимые изменения:

- добавление optional полей;
- добавление новых badge values;
- увеличение числа групп/товаров в разумных пределах.

Несовместимые изменения:

- переименование обязательных полей;
- смена типа `price`;
- смена значения `currency`;
- передача вложенной структуры товаров вместо плоского массива без адаптера;
- добавление кассовых команд в этот каталог.

Если понадобится чек, оплата, РМК или production bridge, это должен быть отдельный контракт, не расширение `CatalogDataContract`.
